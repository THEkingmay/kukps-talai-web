มี Token และเรียก API ผ่านฉลุย → Node.js ส่งข้อมูลกลับมาให้ React แสดงผล
API ตอบกลับ 401 Unauthorized (access_token หมดอายุ) → Axios Interceptor ดักจับ และเรียก /auth/refresh โดยอัตโนมัติ 2. ระบบจัดการ Session & Refresh Token (Node.js + Redis)2.1 การขอ Token ใหม่ (Refresh)เมื่อ Node.js ได้รับ Request ที่ /auth/refresh (ที่ถูกเรียกจาก Axios Interceptor ของ React) จะนำ session_id จาก HTTP-Only Cookie ไปค้นหาใน RedisSession Valid (เจอใน Redis) → ออก access_token ใหม่ (อายุ ~15 นาที) เซ็ตลง Cookie แล้ว React ทำ Request เดิมต่อ
Session Expired/Revoked → ส่ง HTTP 401 → React รับทราบ ล้าง Auth State → Redirect ไปหน้า Login
2.2 TTL Managementsession_id ใน Redis ตั้งค่า TTL = 30 วัน หากไม่มีการใช้งาน Redis จะลบทิ้งอัตโนมัติ3. ระบบจัดการผู้ดูแลระบบ (Super Admin Management)3.1 การเชิญผู้ดูแลระบบใหม่ (Invite Admin)1. Super Admin ระบุ Email ที่ต้องการเชิญผ่านหน้า React 2. Pre-check: Node.js ตรวจสอบใน Main DB ว่า Email ยังไม่มีในระบบ 3. Node.js สร้าง register_key (UUID) บันทึกลง Redis → TTL = 15 นาที 4. ส่ง Email พร้อมลิงก์ที่มี register_key ไปยังผู้ถูกเชิญ
3.2 การจัดการสิทธิ์ & RevocationSuper Admin มีสิทธิ์ เพิ่ม/ลบ สิทธิ์ของ Admin ธรรมดาKick-out Feature: Super Admin สามารถสั่งเตะ Admin ออกจากระบบได้ทันที โดยลบ session_id ออกจาก Redis ทำให้ไม่สามารถ Refresh Token ได้อีก4. การสมัครสมาชิก Admin (Admin Registration)4.1 ผู้ถูกเชิญคลิกลิงก์จาก Email ภายใน 15 นาที (เปิดผ่าน React App)4.2 การตรวจสอบ (Node.js)React จะส่ง register_key ไปให้ Node.js ตรวจสอบ:register_key หมดอายุ (ไม่เจอใน Redis) → ปฏิเสธการสมัคร แจ้งเตือนบน React ให้ Super Admin เชิญใหม่
register_key ยังไม่หมดอายุ → บันทึก Email + Password (Hashed) ลง Main DB
4.3 Single-use Ruleหลังจากสร้าง User สำเร็จ Node.js จะลบ register_key ออกจาก Redis ทันที ป้องกันการใช้ลิงก์ซ้ำ5. ระบบเข้าสู่ระบบ (Login Flow)5.1 Credential VerificationReact ส่ง Email + Password ไปที่ Node.js (/auth/login) เพื่อตรวจสอบกับ Main Database5.2 Session Creationหากข้อมูลถูกต้อง Node.js จะ:1. สร้าง session_id → บันทึกลง Redis ผูกกับ User ID (TTL 30 วัน) 2. ออก access_token (JWT) 3. ส่งทั้งสองค่ากลับไปผ่าน HTTP Response Header (Set-Cookie) แบบ Secure และ HTTP-Only ให้ Browser เป็นผู้จัดการ 4. ตอบกลับ Response Status 200 ให้ React รับทราบเพื่ออัปเดต Auth State และ Redir
